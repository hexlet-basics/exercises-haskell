В этом уроке мы изучим бесконечные последовательности в Haskell. Разберём целочисленные диапазоны без конечной границы, `repeat`, `iterate` и получение ограниченного результата через `take`. Мы научимся соединять такие источники с преобразованием элементов и проверять условия завершения вычисления.

Складу нужны первые три подходящих номера коробок. Правило отбора может меняться, поэтому потребитель заранее не знает, сколько номеров придётся проверить. Источник без конечной границы позволяет отделить генерацию номеров от отбора и количества нужных результатов.

Последовательность можно задать правилом получения очередного элемента без указания последнего. Вычисление по требованию позволяет пользоваться конечной частью такого списка. Конечный запрос определяет нужную часть источника. Для получения результата весь список целиком не вычисляется.

## Источник и конечный результат

Для целых чисел типа `Integer` запись `[start ..]` задаёт возрастающую последовательность с шагом один. Например, программа может формировать номера коробок, начиная с десяти. Первые несколько номеров получаются через `take`.

```haskell
boxNumbers :: [Integer]
boxNumbers = [10 ..]

firstBoxNumbers :: [Integer]
firstBoxNumbers = take 4 boxNumbers
```

В этом коде `boxNumbers` задаёт бесконечный список `Integer`. Значение `firstBoxNumbers` является конечным списком `[10, 11, 12, 13]`. Функция `take` получает требуемое количество типа `Int` и останавливает построение своего результата после этого количества элементов.

При нулевом количестве `take 0 boxNumbers` даёт `[]`. Для определения такого результата элементы источника не нужны. Поэтому количество требуемых элементов является важной частью контракта функции, которая работает с бесконечной последовательностью.

## Отбор подходящих значений

Из источника можно выбирать подходящие номера через известную `filter`. Затем `take` ограничивает количество результатов. Например, текущее правило допускает номера больше двенадцати.

```haskell
selectedBoxNumbers :: [Integer]
selectedBoxNumbers =
  take 3 (filter (\number -> number > 12) boxNumbers)
```

В этом коде `selectedBoxNumbers` равно `[13, 14, 15]`. Отбор пропускает `10`, `11` и `12`. Функция `take` получает уже отобранный список, поэтому три результата требуют проверки шести исходных номеров. При другом правиле это количество может измениться.

Такой запрос завершится, если источник предоставит нужные для поиска части, каждая проверка завершится и достаточно подходящих значений встретится за конечное число проверок. В этом примере все три условия выполняются.

## Повторение и следующее значение

Функция `repeat` задаёт список из повторений одного значения. Например, `take 3 (repeat "ready")` даёт `["ready", "ready", "ready"]`. Тип элемента может быть любым подходящим для задачи, все позиции источника содержат это значение.

Функция `iterate` получает правило перехода к следующему значению и начальный элемент. Начальный элемент входит в результат первым. Далее функция применяется к предыдущему полученному значению. Например, размер очередной партии должен каждый раз удваиваться.

```haskell
batchSizes :: [Integer]
batchSizes = iterate (\size -> size * 2) 3

firstBatchSizes :: [Integer]
firstBatchSizes = take 4 batchSizes
```

В этом коде первые размеры равны `[3, 6, 12, 24]`. Начальное значение `3` появляется до первого применения лямбды. Тот же переход можно записать именованной функцией типа `Integer -> Integer` и передать её в `iterate`.

Последовательность называют продуктивной, если она позволяет получать очередные части результата за конечное число шагов. При этом важно различать структуру списка и значения элементов. Например, `length (take 4 batchSizes)` даёт `4` и требует только структуру префикса. Для получения чисел `[3, 6, 12, 24]` нужны также результаты переходов.

У `iterate` следующий элемент задаётся применением правила к предыдущему. Его значение может оставаться невостребованным при наблюдении структуры списка. У приведённого правила удвоения нужные вычисления завершаются. Для другого правила проверка завершения должна учитывать, какие значения запросит потребитель и можно ли их вычислить.

## Преобразование до ограничения

Готовый источник можно преобразовывать через `map`. Например, номер коробки превращается в текстовую подпись, после чего выбираются три первые подписи.

```haskell
boxLabels :: [String]
boxLabels = map (\number -> "Box " ++ show number) boxNumbers

previewLabels :: [String]
previewLabels = take 3 boxLabels
```

В этом коде `previewLabels` равно `["Box 10", "Box 11", "Box 12"]`. Функция `show` формирует текст отдельного числа. Схема показывает, как конечный запрос ограничивает нужную часть преобразованного источника.

```text
[10, 11, 12, 13, ...]
          |
          map с функцией подписи
          |
["Box 10", "Box 11", "Box 12", ...]
          |
          take 3
          |
["Box 10", "Box 11", "Box 12"]
```

На этой схеме источнику достаточно предоставить три числа, чтобы получить полный результат `previewLabels`. Остальные подписи не требуются для этого запроса. Исходное правило генерации при этом остаётся доступным для другого количества элементов.

## Когда ограничение не помогает

Условия успешного отбора важны даже для запроса одного элемента. Следующий пример намеренно не завершает поиск первого результата.

<!-- lint-code-blocks: skip — намеренно незавершающийся поиск в бесконечном источнике -->

```text
take 1 (filter (\number -> number < 0) boxNumbers)
```

В этом выражении все числа источника неотрицательны. Поиск не встретит подходящий элемент и не достигнет конца источника. Такой отбор непродуктивен на уровне структуры, поскольку не позволяет получить даже первый конструктор результата. Одного `take` для завершения такого поиска недостаточно.

Получение длины `length boxNumbers` потребовало бы дойти до конца списка и не даст результата. Поэтому сначала выбирают конечную часть, если дальнейшая операция требует полного обхода всех её элементов.
