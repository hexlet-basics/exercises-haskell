В этом уроке мы изучим вычисление по требованию в Haskell. Разберём, какие части входных данных нужны для получения выбранного результата. Мы научимся различать структуру списка и значения его элементов и избегать лишних требований к данным.

Пара показаний может содержать быстрый расчёт текущей температуры и длительный расчёт среднего за месяц. Отчёту с текущей температурой среднее не нужно. Обязательное вычисление обоих полей задержало бы получение нужного результата из-за посторонней для него работы.

Чистое выражение описывает значение и зависимости, по которым его можно получить. Нестрогость Haskell означает, что результат может быть определён даже при невостребованной части входа, которую вычислить не удаётся. GHC реализует такую семантику вычислением по требованию, которое также называют ленивым. Нужные данные вычисляются по зависимостям результата.

Если результат действительно зависит от значения, его всё равно потребуется получить. Поэтому при разборе важно уточнять, какой именно результат мы хотим узнать. Одно вычисление может требовать всю структуру списка, другое только один его элемент.

## Нужная часть данных

Пусть пара хранит два показания, а для текущего отчёта нужно только первое. Извлечение первого показания можно описать через знакомое сопоставление с образцом.

```haskell
firstReading :: (Integer, Integer) -> Integer
firstReading (first, _) = first
```

В этой функции результат зависит от первого поля пары. Образец должен распознать саму пару, но значение второго поля для результата не требуется. Подчёркивание показывает, что определение его не использует.

Для исследования подготовим намеренно ошибочное вычисление во втором поле. Функция `error :: String -> a` отмечает вычисление, обращение к результату которого завершилось бы ошибкой с указанным текстом. Параметр `a` позволяет поставить такое выражение на место значения любого типа. Здесь оно моделирует часть данных, которую невозможно успешно получить.

```haskell
firstReading (18, error "unused second reading") -- 18
```

В этом примере первое поле содержит готовое число `18`. Ошибочное второе поле не нужно для получения этого числа. Схема показывает зависимость результата от частей входа.

```text
пара
 ├── первое поле 18 ───────────> результат 18
 └── второе поле с ошибкой ────× не требуется
```

На этой схеме стрелка связывает первое поле с результатом. Крест отмечает отсутствие требования ко второму полю. Нестрогость сохраняет ошибочное выражение невостребованным только тогда, когда результат от него не зависит.

## Структура списка и его элементы

Список состоит из пустого списка `[]` или конструктора `:`, связывающего элемент с оставшимся списком. Чтобы узнать количество элементов конечного списка, достаточно пройти по этой структуре до `[]`. Само числовое значение каждого элемента для подсчёта не требуется.

Это различие можно проверить на подготовленном списке с одним ошибочным элементом. В следующем исследовательском примере `error` снова отмечает значение, которое нельзя вычислить успешно.

```haskell
length [error "unavailable element", 7, 18] -- 3
```

Здесь известна структура из трёх элементов, заканчивающаяся пустым списком. Поэтому `length` даёт `3`. Получение первого элемента как числа, например для сложения, потребовало бы ошибочного вычисления.

Отдельно рассмотрим ситуацию, когда неизвестен сам оставшийся список. Его можно отметить ошибочным хвостом после двух доступных элементов.

```haskell
take 2 (12 : 7 : error "unavailable tail") -- [12, 7]
```

В этом примере для первых двух элементов достаточно двух известных конструкторов `:`. Функция `take` ограничивает нужную часть результата, и отмеченный хвост не востребован.

Нулевой запрос не требует даже первого конструктора списка. Например, следующий вызов возвращает пустой список без обращения к подготовленному входу.

```haskell
take 0 (error "unavailable input" :: [Integer]) -- []
```

В этом выражении аннотация задаёт входу тип `[Integer]`. Для результата `[]` значение этого входа не требуется.

## Лишнее требование к данным

Перед выбором двух элементов можно по ошибке проверить длину всего списка. Следующий вариант намеренно создаёт лишнее требование к данным.

<!-- lint-code-blocks: skip — намеренный отказ из-за востребования ошибочного хвоста -->

```text
firstTwoChecked :: [Integer] -> [Integer]
firstTwoChecked values =
  if length values >= 2
    then take 2 values
    else values

firstTwoChecked (12 : 7 : error "unavailable tail")
```

При запросе результата в GHCi этот вызов завершается следующим отказом.

```text
*** Exception: unavailable tail
```

В этом определении проверка `length values >= 2` требует пройти до конца списка. Поэтому она обращается к ошибочному хвосту, хотя нужные два элемента уже доступны. Прямой вызов `take 2` выше даёт `[12, 7]` на том же входе и сам обрабатывает список короче запроса. Для исправления достаточно убрать предварительную проверку длины.

## Требования задаёт использование результата

Даже выбранную часть списка можно исследовать по-разному. Например, подсчёт длины префикса требует его структуру. Получение всех числовых значений того же префикса дополнительно требует элементы. Поэтому корректный отбор начала списка должен сохранять возможность отложить вычисление этих элементов до их использования.

В определении может присутствовать выражение, значение которого не потребуется в выбранном результате. Так происходит и у невыбранной ветви `if`. Описание вычисления через имена и функции помогает проследить эти зависимости. Запись определений сама по себе не задаёт обязательный порядок вычисления всех их частей.

Подготовленные ошибки в примерах служат исследованию зависимостей. В обычном решении задачи они не нужны. Вычисление по требованию также само по себе не гарантирует завершения любого определения и не обещает определённого расхода памяти. Мы проверяем, какие части данных нужны конкретному наблюдаемому результату.
