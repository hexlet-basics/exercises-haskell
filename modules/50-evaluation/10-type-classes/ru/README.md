В этом уроке мы изучим классы типов и ограничения в сигнатурах Haskell. Разберём требования к сравнению, текстовому представлению и знакомым числовым операциям. Мы научимся описывать нужные операции для обобщённой функции и автоматически получать некоторые из них для собственного типа.

Обобщённая функция может использовать значение неизвестного типа, например поместить его в пару. Для сравнения двух таких значений нужно дополнительное основание. Возможность сравнения определяется типом и поддерживаемыми им операциями. Класс типов задаёт набор операций, а ограничение в сигнатуре сообщает, что выбранный тип должен их поддерживать.

## Ограничение Eq

Класс `Eq` описывает проверку равенства. Оператор в круглых скобках, например `(==)`, обозначает имя функции. Так можно показать его тип или передать такую функцию аргументом. Полная сигнатура операции равенства записывается как `(==) :: Eq a => a -> a -> Bool`. Часть `Eq a` перед `=>` является ограничением. Остальная часть показывает обычные аргументы и результат.

Например, функция может проверить, совпадают ли два компонента пары.

```haskell
samePair :: Eq a => (a, a) -> Bool
samePair (left, right) = left == right
```

В этом коде оба компонента имеют один тип `a`, для которого доступны операции `Eq`. Применение `samePair (12, 12)` даёт `True`, а `samePair ("North", "South")` даёт `False`. У `Integer` и `String` уже есть нужные реализации сравнения.

Если убрать `Eq a`, сигнатура будет обещать работу с любым типом без дополнительных требований. В следующем определении операция `==` требует возможности, которую сигнатура не гарантирует.

<!-- lint-code-blocks: skip — намеренно пропущено ограничение Eq для сравнения значений -->
```text
samePair :: (a, a) -> Bool
samePair (left, right) = left == right
```

При проверке этого определения GHC сообщает об отсутствующем ограничении. Ключевая часть сообщения выглядит так.

```text
    • No instance for (Eq a) arising from a use of ‘==’
      Possible fix:
        add (Eq a) to the context of
```

Слова `arising from a use of ‘==’` указывают на применение равенства. Часть `No instance for (Eq a)` означает, что компилятор не может подтвердить поддержку `Eq` для произвольного `a`. Подсказка `add (Eq a)` предлагает добавить это требование в сигнатуру. Ограничение `Eq a =>` из первого определения согласует обещания функции с операцией в её теле.

## Стандартные операции и несколько требований

Классы типов описывают разные возможности значения.

| Класс | Доступные операции |
| --- | --- |
| `Eq` | Равенство `==` и неравенство `/=` |
| `Ord` | Упорядочивание через `<`, `<=`, `>` и `>=` |
| `Show` | Получение текстового представления через `show` |

В этой таблице `show` возвращает строку, представляющую значение. Её полная сигнатура записывается как `show :: Show a => a -> String`. Например, `show 12` даёт `"12"`. Для строк и собственных типов представление может включать кавычки или имена конструкторов, поэтому оно удобно для диагностики.

Несколько ограничений записываются в скобках через запятую. Например, функция выбирает большее из двух значений и возвращает его текстовое представление.

```haskell
largerText :: (Ord a, Show a) => a -> a -> String
largerText left right = show (if left >= right then left else right)
```

В этой функции `Ord a` разрешает сравнение, а `Show a` позволяет применить `show` к выбранному значению. Для `largerText 12 5` результатом будет строка `"12"`. Условия перед `=>` вместе описывают все дополнительные операции, необходимые этому определению.

Числовые вычисления и чтение значений используют другие стандартные классы.

| Класс | Роль |
| --- | --- |
| `Num` | Сложение, вычитание, умножение и целочисленные литералы |
| `Integral` | Операции над целыми типами, включая `div` и `mod` |
| `Read` | Чтение значения из его текстовой записи |

Связь строк `Integral` и `Num` в этой таблице видна в полном типе `fromIntegral :: (Integral a, Num b) => a -> b`. Исходное значение должно иметь целый тип с поддержкой `Integral`, а результат получает числовой тип с поддержкой `Num`. Конкретный тип результата определяется контекстом, например сигнатурой функции.

Строка `Read` в таблице относится к чтению значений, например через `readMaybe :: Read a => String -> Maybe a`. Ограничение `Read a` задаёт возможность прочитать значение типа `a`. Предметные требования, например положительное количество товара, проверяются отдельно после разбора строки.

## Автоматическое получение операций

Для простых собственных типов некоторые стандартные операции может создать компилятор. В объявление добавляется `deriving` со списком нужных классов. Например, тип пропуска содержит строковый код и номер зоны.

```haskell
data Pass = PassCode String Integer
  deriving (Eq, Show)
```

В этом объявлении `deriving (Eq, Show)` создаёт для `Pass` сравнение и текстовое представление. Два пропуска считаются равными, если совпадают их конструкторы и все данные. Поэтому сравнение `PassCode "A" 2 == PassCode "A" 2` даёт `True`, а разные номера зон дадут `False`.

Применение `show (PassCode "A" 2)` получает строку с содержимым `PassCode "A" 2`. Чтобы автоматически получить `Eq`, типы всех полей должны поддерживать `Eq`. Для автоматического `Show` им нужны операции `Show`. У `String` и `Integer` эти возможности уже есть.

Ограничение у функции описывает нужные операции для её аргументов, а `deriving` предоставляет выбранные стандартные операции собственному типу. Благодаря этому одно обобщённое определение можно применять к разным подходящим типам, сохраняя явный контракт его возможностей.
