В этом уроке мы изучим рекурсивные типы данных в Haskell. Разберём объявление рекурсивного типа и построение конечного дерева. Мы научимся обходить такую структуру по её форме и задавать базовые случаи для конечных элементов.

Одно значение может содержать несколько более мелких значений того же типа. Например, документ состоит из отдельной строки либо из двух документов, расположенных друг за другом. Каждый из этих документов тоже может состоять из нескольких частей. Рекурсивное объявление типа описывает такую вложенность одним правилом.

## Тип с частями того же типа

Для документа определим два конструктора. `TextLine` содержит текст отдельной строки. `Stack` объединяет верхнюю и нижнюю части, каждая из которых имеет тип `Document`.

```haskell
data Document
  = TextLine String
  | Stack Document Document
```

В этом объявлении имя `Document` встречается и слева, и в полях конструктора `Stack`. Поэтому тип является рекурсивным. Конструктор `TextLine` не содержит вложенного `Document` и позволяет завершить построение. В этом уроке мы работаем с конечными значениями, которые в итоге состоят из таких строк.

Например, небольшой документ может содержать одну строку сверху и ещё две строки в нижней части.

```haskell
sampleDocument :: Document
sampleDocument =
  Stack
    (TextLine "North")
    (Stack (TextLine "East") (TextLine "West"))
```

В этом коде оба аргумента внешнего `Stack` имеют тип `Document`. Первый построен через `TextLine`, второй через ещё один `Stack`. Скобки выделяют отдельные составные аргументы. Схема показывает полученную структуру.

```text
Stack
  +-- TextLine "North"
  +-- Stack
        +-- TextLine "East"
        +-- TextLine "West"
```

На этой схеме значения `TextLine` являются листьями дерева, у них нет дочерних документов. Значения `Stack` являются узлами с двумя дочерними частями. Вложенность показывает, какие части объединяются в одно целое.

## Обход структуры

Функция обработки дерева разбирает его конструктор. Для листа результат задаётся непосредственно. Для узла функция рекурсивно обрабатывает дочерние части и соединяет их результаты. На конечном дереве каждый такой переход приближает вычисление к листьям.

Например, документ нужно преобразовать в обычную строку текста с переводами строк между частями.

```haskell
renderDocument :: Document -> String
renderDocument (TextLine text) = text
renderDocument (Stack top bottom) =
  renderDocument top ++ "\n" ++ renderDocument bottom
```

В этой функции случай `TextLine` сразу возвращает хранимую строку. В случае `Stack` получаются результаты для верхней и нижней части. Между ними добавляется `"\n"`, строка из одного символа перевода строки. Применение `renderDocument sampleDocument` даёт строку `"North\nEast\nWest"`.

Схема раскрывает несколько вызовов для этого значения.

```text
renderDocument sampleDocument
= renderDocument (TextLine "North") ++ "\n"
    ++ renderDocument (Stack (TextLine "East") (TextLine "West"))
= "North" ++ "\n"
    ++ (renderDocument (TextLine "East") ++ "\n"
          ++ renderDocument (TextLine "West"))
= "North\nEast\nWest"
```

В этой развёртке отдельные строки дают базовые результаты, а каждый узел соединяет результаты своих частей. Рекурсивные вызовы получают дочерние документы. Передавать в них весь исходный документ повторно не требуется, поскольку задача уже разбита по его структуре.

## Базовый случай и конечный вход

У списка при разборе непустого случая остаётся один список для дальнейшего обхода. У нашего дерева узел содержит две части. Поэтому общий результат должен учитывать обе, каждую по тому же правилу обработки `Document`.

На конечном дереве дочерняя часть содержит меньше конструкторов, чем узел вместе с его частями. Каждый путь обхода доходит до `TextLine`, где рекурсивного вызова больше нет. Наличие такого случая и переход к меньшим частям объясняют завершение полного обхода.

Выбор результата базового случая зависит от задачи. В функции отображения лист возвращает свой текст. При вычислении некоторого общего количества лист может давать число. Правило для узла затем объединит два результата нужным способом. Тип объявления определяет форму данных, а функция определяет смысл их обработки.

Оба конструктора требуют обработки. Если описать только `TextLine`, программа не сможет обработать составной документ. Если пропустить одну из дочерних частей `Stack`, результат не учтёт весь документ. Явные образцы и разбор небольшого дерева помогают проверить эти два условия.
