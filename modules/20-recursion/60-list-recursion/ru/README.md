В этом уроке мы изучим рекурсию по списку в Haskell. Разберём обработку пустого списка и переход от первого элемента к оставшейся части. Мы научимся строить новый список и объяснять, почему вычисление завершается на конечном входе.

Список задаёт удобный способ уменьшать задачу. Непустое значение разбирается на первый элемент и оставшийся список. Если применить функцию к оставшейся части, она получит меньше элементов. Пустой список задаёт базовый случай, для которого результат определяется сразу. Такую рекурсию по составным частям данных называют структурной.

## Обработка одного элемента и остатка

Для рекурсивного определения нужны два случая. Образец `[]` описывает отсутствие элементов. Образец `value : rest` выделяет текущее значение и меньший список, который передаётся рекурсивному вызову. Правило обработки текущего значения связывается с результатом этого вызова.

Например, датчик записал показания с постоянным смещением. Для калибровки нужно прибавить поправку к каждому показанию. Функция получает поправку и исходный список, затем возвращает список скорректированных значений в том же порядке.

```haskell
addCalibration :: Integer -> [Integer] -> [Integer]
addCalibration _ [] = []
addCalibration offset (value : rest) =
  (value + offset) : addCalibration offset rest
```

В этой функции пустому входному списку соответствует пустой результат. В непустом случае выражение `value + offset` вычисляет новое показание. Рекурсивный вызов `addCalibration offset rest` описывает обработку остальных показаний. Оператор `:` связывает новое значение с результирующим списком остальных значений.

Первый аргумент `offset` сохраняется при рекурсивном вызове. Уменьшается второй аргумент, список. Например, для поправки `3` и показаний `[4, 7, 2]` получится `[7, 10, 5]`. Схема раскрывает применение определения к этим трём элементам.

```text
addCalibration 3 [4, 7, 2]
= (4 + 3) : addCalibration 3 [7, 2]
= 7 : ((7 + 3) : addCalibration 3 [2])
= 7 : (10 : ((2 + 3) : addCalibration 3 []))
= 7 : (10 : (5 : []))
= [7, 10, 5]
```

В этой развёртке каждый рекурсивный вызов получает список без уже выделенного первого элемента. Случай `[]` даёт основу результирующего списка. Равенства показывают смысл определения на конкретном входе, без требования к порядку вычисления отдельных числовых выражений.

## Почему рекурсия завершается

На конечном входе переход от `value : rest` к `rest` уменьшает число оставшихся элементов на один. После трёх таких переходов список из трёх показаний становится пустым. Базовый случай возвращает `[]` и не содержит нового рекурсивного вызова.

Само наличие образца `[]` ещё не гарантирует завершение. Рекурсивный вызов должен приближаться к этому случаю. Например, следующий фрагмент намеренно ошибочен.

<!-- lint-code-blocks: skip — рекурсия намеренно повторно получает весь список -->

```text
broken :: [Integer] -> [Integer]
broken [] = []
broken (value : rest) = value : broken (value : rest)
```

В этом определении повторно передаётся весь непустой список `value : rest`. Он не уменьшается. Поэтому функция не сможет построить полный конечный результат для такого входа. Для прохода по конечному списку в рекурсивный вызов передаётся именно `rest`.

## Построение результата

В примере калибровки каждый исходный элемент даёт один новый элемент. Поэтому длина результата совпадает с длиной входа. В других задачах текущий элемент может не понадобиться в ответе. Тогда результатом данного шага может стать обработанный остаток без присоединения текущего элемента через `:`. Выбор между этими действиями можно записать обычным условным выражением.

Порядок сохранённых элементов определяется тем, как мы соединяем результаты. Если обработанный текущий элемент ставится перед результатом обработки `rest`, он остаётся перед элементами, которые следовали за ним во входе. Добавление в конец потребовало бы другого построения выражения.

Исходное значение списка при этом сохраняется. Разбор через образец даёт имена его частям, а `:` строит значение результата. Поэтому исходные показания можно передать в другую функцию и получить ещё один результат с другой поправкой. Для самого преобразования не требуется менять элементы входного списка.
