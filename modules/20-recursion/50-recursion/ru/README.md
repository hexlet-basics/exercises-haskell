В этом уроке мы изучим рекурсивные функции в Haskell. Разберём базовый случай, переход к меньшей задаче и получение результата из рекурсивного вызова. Мы научимся прослеживать конечную цепочку применений функции и проверять условия её завершения.

Некоторые задачи удобно разбивать на одно простое действие и оставшуюся работу того же вида. Если для остатка подходит та же функция, её определение может использовать применение этой функции к меньшему входу. Такой способ описания вычисления называется рекурсией.

Для завершения нужны случаи, результат которых уже известен и не требует нового рекурсивного вызова. Их называют базовыми случаями. Остальные случаи задают рекурсивный шаг. Он должен приближать задачу к одному из базовых случаев, сохраняя смысл вычисления.

## Задача с меньшим количеством предметов

Пусть предметы нужно разложить по коробкам вместимостью три предмета. Последняя коробка может быть заполнена частично. Для пустого набора коробки не нужны. Количество предметов в этой модели всегда является неотрицательным целым числом.

Если предметов от одного до трёх, достаточно одной коробки. Когда предметов больше трёх, можно заполнить одну коробку и вычислить, сколько коробок потребуется для оставшихся предметов. Эту оставшуюся работу описывает та же функция.

```haskell
boxCount :: Integer -> Integer
boxCount items
  | items == 0 = 0
  | items <= 3 = 1
  | otherwise = 1 + boxCount (items - 3)
```

В этой функции первые две ветви являются базовыми случаями. Они возвращают готовое значение `0` или `1`. Последняя ветвь описывает одну заполненную коробку через число `1` и оставшиеся коробки через `boxCount (items - 3)`.

Выражение `items - 3` находится в скобках, поскольку его результат должен стать аргументом `boxCount`. Сам аргумент `items` при этом сохраняется. Новое применение функции получает другое значение. Например, при входе `7` внешний вызов работает с семью предметами, а вложенный получает четыре.

## Цепочка применений

Чтобы получить значение `boxCount 7`, требуется результат `boxCount 4`. Для него требуется результат `boxCount 1`. Схема показывает уменьшение задачи.

```text
boxCount 7     нужно получить 1 + boxCount 4
    |
    v
boxCount 4     нужно получить 1 + boxCount 1
    |
    v
boxCount 1     готовый результат 1
```

На этой схеме аргумент уменьшается на три при каждом рекурсивном шаге. Значение `1` попадает в базовый случай. Поэтому для него уже не требуется ещё одно применение `boxCount`.

Теперь известные результаты позволяют получить результаты больших задач. Обратный разбор выражений выглядит так.

```text
boxCount 1 = 1
boxCount 4 = 1 + 1 = 2
boxCount 7 = 1 + 2 = 3
```

Здесь каждое сложение добавляет одну коробку к результату для меньшего количества предметов. В итоге семи предметам нужны три коробки. Для `boxCount 0` цепочка будет состоять только из первого базового случая и сразу даст `0`.

Такой разбор можно выполнить вручную на небольшом входе. Он помогает проверить и направление уменьшения, и действие, которое объединяет текущую часть задачи с результатом для остатка. Для другого алгоритма этим действием может быть другое вычисление, соответствующее его условию.

## Почему вычисление завершается

В `boxCount` рекурсивная ветвь выбирается только для количества больше трёх. После вычитания трёх получается меньшее положительное число. Повторяя этот шаг, мы дойдём до значения от одного до трёх. Для исходного нуля предусмотрена отдельная ветвь. Это объясняет завершение для всех допустимых входов модели.

Наличие функции с тем же именем справа от `=` само по себе не обеспечивает завершения. Например, следующее определение намеренно содержит ошибку.

<!-- lint-code-blocks: skip — рекурсия намеренно не уменьшает аргумент -->

```text
stuck :: Integer -> Integer
stuck n = 1 + stuck n
```

В этом примере аргумент вложенного применения совпадает с исходным. Базовый случай отсутствует, поэтому получить готовое число для сложения невозможно.

При чтении рекурсивной функции полезно найти готовый результат, проверить изменение аргумента и проследить несколько шагов до этого результата. Если допустимые входы ограничены неотрицательными числами, это ограничение нужно учитывать при проверке уменьшения. Обработка других входов требует отдельного правила.
