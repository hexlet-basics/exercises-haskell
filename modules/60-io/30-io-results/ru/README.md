В этом уроке мы изучим действия `IO` с полезным результатом. Разберём применение `pure` в контексте `IO` и связь результата блока `do` с его последним действием. Мы научимся возвращать вычисленное значение из действия и определять тип всего блока.

Взаимодействие с внешним миром и результат вычисления выполняют разные роли. Действие может показать сообщение и предоставить вызывающей стороне дополнительное значение для дальнейшей работы. Тип `IO a` описывает действие с результатом типа `a`. При этом значение самого действия и полученный при его исполнении результат имеют разные типы.

## Готовое значение в действии

В контексте `IO` функция `pure` создаёт действие, результатом которого служит переданное значение. Само это действие не добавляет внешних эффектов. Например, готовое целое число можно представить результатом действия.

```haskell
asAction :: Integer -> IO Integer
asAction number = pure number
```

В этом коде `asAction 7` имеет тип `IO Integer`. Если это действие исполнено, оно предоставляет результат `7`. Строка с числом на экране от одного `pure` не появляется, поскольку действие вывода здесь не задано.

Сигнатура `asAction` определяет, что `pure` используется именно для `IO`. В этом контексте её применение можно читать как преобразование типа `a -> IO a`. Это выбранная специализация библиотечной функции, у которой есть и другие применения. Общую сигнатуру `pure` здесь не разбираем.

## Сообщение и возвращаемое значение

Например, учебная программа показывает текст уведомления и предоставляет количество слов в нём. Текст нужен получателю сообщения, а число может использовать другая часть программы.

```haskell
announce :: String -> IO Int
announce message = do
  putStrLn message
  pure (length (words message))
```

В этом коде первое действие выводит переданный текст с переводом строки. Последнее действие предоставляет вычисленное количество слов. Для `announce "Room ready"` на экране появляется одна строка `Room ready`, а результатом исполнения действия служит число `2` типа `Int`.

Схема разделяет видимый вывод и значение, которое получает вызывающая сторона.

```text
announce "Room ready" :: IO Int
               |
           исполнение
            /      \
           v        v
        вывод    результат Int
     Room ready       2
```

В этой схеме вывод получается благодаря `putStrLn`. Число `2` предоставляется как результат последнего действия `pure`. Оно не становится дополнительной строкой вывода. Функция описывает действие, у которого есть видимый вывод и возвращаемое значение.

Использовать полезный результат действия в последующем вычислении мы научимся при чтении ввода в следующем уроке. В практике этого урока возвращаемое значение получают тесты и проверяют его отдельно от вывода.

## Последнее действие блока

Тип результата всего `do` определяется его последним действием. В `announce` последняя строка имеет тип `IO Int`, поэтому весь блок имеет тип `IO Int`. Промежуточное `putStrLn message` имеет тип `IO ()`, что согласуется с его ролью вывода сообщения.

Если последнее действие предоставляет `Bool`, блок получает тип `IO Bool`. Если оно предоставляет `()`, тип блока равен `IO ()`. Сигнатура функции должна согласовываться с этим типом. Чистое значение в последней строке нужно оформить как действие, например через `pure` в выбранном контексте `IO`.

`pure` может стоять и перед другими действиями. Например, следующий блок продолжает выполнение после первой строки.

```haskell
stillRuns :: IO ()
stillRuns = do
  pure ()
  putStrLn "Next action"
```

В этом коде после `pure ()` исполняется `putStrLn`, поэтому появляется строка `Next action`. Промежуточный результат первой строки не становится результатом всего блока. `pure` создаёт действие для значения, а порядок продолжения задаётся окружающим `do`.

Полезный результат действия выбирается с учётом задачи функции. Для уведомления полезным результатом стало число слов, а для проверки данных им может быть логический признак допустимости. Тип такого признака будет `Bool`, а описывающее взаимодействие действие получит тип `IO Bool`.
