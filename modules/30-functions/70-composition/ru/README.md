В этом уроке мы изучим композицию функций в Haskell. Разберём соединение преобразований через `.` и применение функции через `$`. Мы научимся согласовывать типы соседних преобразований и читать направление передачи результата.

Когда результат одного вычисления нужен другому, функции можно соединить в новое преобразование. Композиция `f . g` строит функцию, которая передаёт результат `g` в `f`. Для аргумента `value` выражение `(f . g) value` означает `f (g value)`.

Таким образом, данные проходят через правую функцию к левой. Соединение возможно, когда тип результата правой функции подходит типу аргумента левой. Само выражение `f . g` является значением функции, которое можно применить к данным или передать дальше.

## Цепочка преобразований

Например, учебная программа готовит текстовый отчёт по показаниям датчика. Отрицательные показания отбрасываются. Допустимое значение меньше 50 получает подпись `"low"`, остальные значения подпись `"high"`. В отчёте подписи соединяются пробелами.

```haskell
validReading :: Integer -> Bool
validReading reading = reading >= 0

readingLabel :: Integer -> String
readingLabel reading = if reading < 50 then "low" else "high"

reportWithCalls :: [Integer] -> String
reportWithCalls readings = unwords (map readingLabel (filter validReading readings))
```

В этом коде `filter validReading` отбирает допустимые показания. Функция `map readingLabel` получает выбранные числа и строит список подписей. Вызов `unwords` объединяет подписи в строку. Для `reportWithCalls [10, -1, 80]` результатом будет `"low high"`.

Каждый из этих этапов уже является функцией с одним оставшимся аргументом. Это позволяет соединить их через композицию.

```haskell
readingReport :: [Integer] -> String
readingReport readings = (unwords . map readingLabel . filter validReading) readings
```

В этом коде выражение в скобках строит функцию типа `[Integer] -> String`. К ней применяется `readings`. Преобразования в записи идут справа налево, поэтому ближайший к данным этап `filter validReading` написан справа. Применение `readingReport [10, -1, 80]` даёт ту же строку `"low high"`.

Применение функции к аргументу связывает сильнее оператора `.`. Поэтому `map readingLabel` и `filter validReading` образуют отдельные функции, которые соединяет композиция. Сам оператор `.` группируется вправо. С явными скобками запись имеет вид `(unwords . ((map readingLabel) . (filter validReading))) readings`. Здесь `readingLabel` становится аргументом `map`, а `validReading` становится аргументом `filter`.

Схема показывает движение данных и тип на каждой границе преобразований.

```text
[Integer]
    |
filter validReading
    |
    v
[Integer]
    |
map readingLabel
    |
    v
[String]
    |
 unwords
    |
    v
  String
```

В этой схеме отбор сохраняет тип элементов списка, преобразование меняет числа на строки, а объединение превращает список строк в одну строку. Направление схемы следует за данными. Запись композиции описывает те же связи начиная с функции, которая формирует конечный результат.

## Согласование типов

При построении композиции компилятор проверяет промежуточный тип. Например, `map readingLabel` имеет здесь тип `[Integer] -> [String]`. Функция `unwords` принимает `[String]` и возвращает `String`, поэтому эти два этапа согласованы.

Если соединить напрямую функции `readingLabel` и `validReading`, согласование нарушится. Следующее определение намеренно содержит ошибку типов.

<!-- lint-code-blocks: skip — сознательно неверная композиция с несовместимыми промежуточными типами -->
```text
wrong = readingLabel . validReading
```

При проверке этого определения GHC 9.0.2 сообщает о несовместимости. Ключевая часть фактической диагностики выглядит так.

```text
Couldn't match type ‘Bool’ with ‘Integer’
Expected: Integer -> Integer
  Actual: Integer -> Bool
In the second argument of ‘(.)’, namely ‘validReading’
```

Здесь `Actual` показывает тип переданной функции `validReading`, результатом которой служит `Bool`. В строке `Expected` компилятор ожидает функцию с результатом `Integer`, поскольку это входной тип `readingLabel`. Несовместимость возникает на границе между двумя функциями. Компилятор отклоняет такую композицию до запуска программы.

Композицию можно описать и общей сигнатурой. Для функции `g :: a -> b` и функции `f :: b -> c` результат `f . g` имеет тип `a -> c`. Повторение `b` отмечает точку соединения двух функций. Типы `a` и `c` задают вход и результат полученного преобразования.

## Применение с низким приоритетом

Оператор `$` применяет функцию слева к аргументу справа. Выражение `f $ value` означает `f value`. У `$` низкий приоритет, поэтому справа можно записать целое выражение без дополнительных скобок вокруг него.

Например, вложенные вызовы для отчёта можно записать так.

```haskell
reportWithApply :: [Integer] -> String
reportWithApply readings = unwords $ map readingLabel $ filter validReading readings
```

В этом коде правые части группируются как `unwords (map readingLabel (filter validReading readings))`. Результат `reportWithApply [10, -1, 80]` равен `"low high"`. Оператор `$` возвращает результат применения функции к аргументу. Для построения функции из нескольких преобразований служит `.`.

В определении `readingReport` имя аргумента оставлено явно. Скобки отделяют построение функции через композицию от её применения к `readings`. Такое оформление позволяет отдельно увидеть цепочку преобразований и данные, к которым она применяется.
