В этом уроке мы изучим преобразование элементов списка через `map`. Разберём передачу функции обработки и связь типов входного списка с результатом. Мы научимся получать новый список с сохранением порядка и менять тип его элементов.

Для многих задач требуется одинаково обработать каждый элемент последовательности. Например, числовые показания можно превратить в текстовые описания. У правила обработки одного показания и у обхода всего списка разные роли. Функция `map` соединяет их, принимая правило преобразования и применяя его к каждому элементу.

## Правило для одного элемента

Сначала определим, как обрабатывается одно значение. Пусть приложению нужны подписи, которые отличают отрицательные показания от неотрицательных. Для одного целого показания достаточно функции с результатом `String`.

```haskell
readingLabel :: Integer -> String
readingLabel reading =
  if reading < 0
    then "negative"
    else "non-negative"
```

В этой функции `readingLabel (-2)` даёт `"negative"`, а `readingLabel 5` даёт `"non-negative"`. Нулю тоже соответствует строка `"non-negative"`. Правило определено для каждого целого показания и возвращает ровно одну строку.

Теперь это правило можно передать `map` вместе со списком показаний.

```haskell
readingLabels :: [Integer] -> [String]
readingLabels readings = map readingLabel readings
```

В этом коде первым аргументом `map` является сама функция `readingLabel`. Второй аргумент содержит список. Применение `readingLabels [-2, 0, 5]` даёт `["negative", "non-negative", "non-negative"]`. Каждый элемент результата соответствует показанию на той же позиции входного списка.

Схема показывает эти отдельные соответствия.

```text
Вход           -2                 0                    5
                |                 |                    |
Правило    readingLabel      readingLabel         readingLabel
                |                 |                    |
Результат  "negative"       "non-negative"       "non-negative"
```

На этой схеме три исходных числа дают три строки. Два разных показания получили одинаковую подпись, и обе строки остаются в результате. `map` сохраняет число элементов и их порядок, даже когда полученные значения повторяются.

## Как читается тип map

Сигнатура `map :: (a -> b) -> [a] -> [b]` связывает тип правила с типами списков. Её части выполняют разные роли.

| Часть сигнатуры | Роль |
| --- | --- |
| `(a -> b)` | Тип функции преобразования одного элемента |
| `[a]` | Тип исходного списка |
| `[b]` | Тип результирующего списка |

Для `readingLabel` переменная `a` становится `Integer`, а `b` становится `String`. Поэтому исходный список содержит числа, а результат содержит строки. Тип аргумента переданной функции должен совпадать с типом элемента исходного списка.

Переменные `a` и `b` допускают и одинаковый тип. Например, преобразование одного числа в другое даст список чисел. Преобразование каждой строки в её длину даст список значений `Int`, поскольку результат `length` для строки имеет этот тип. В каждом случае тип результата определяется переданным правилом.

## Пустой список и рекурсивный смысл

На пустом списке `map` возвращает пустой список. Элементов для преобразования нет, поэтому выражение `readingLabels []` даёт `[]`. Для списка из одного показания результат содержит одну строку. Дополнительная проверка длины перед применением `map` не требуется.

Тот же смысл можно выразить рекурсивной обработкой списка. Для функции подписей получится такое определение.

```haskell
readingLabelsRecursive :: [Integer] -> [String]
readingLabelsRecursive [] = []
readingLabelsRecursive (reading : rest) =
  readingLabel reading : readingLabelsRecursive rest
```

В этом коде пустой список задаёт базовый случай. Для непустого списка `readingLabel` создаёт подпись текущего показания, а рекурсивный вызов обрабатывает оставшиеся. Оператор `:` собирает результат в исходном порядке. Выражение с `map` передаёт общее правило такого преобразования готовой функции.

Вместо именованного правила можно передать лямбду или полученную функцию, если её тип подходит элементам списка. Например, `map (\reading -> reading * 2) [3, 7]` даёт `[6, 14]`. Лямбда задаёт правило удвоения каждого показания прямо в месте применения `map`.

Сам исходный список остаётся доступен. Например, одни и те же показания можно преобразовать в подписи и отдельно передать функции числовой обработки. Каждый результат определяется своим правилом преобразования.
