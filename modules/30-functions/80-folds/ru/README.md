В этом уроке мы изучим свёртку списка через `foldr`. Разберём функцию шага, базовый результат и расположение скобок при объединении элементов. Мы научимся получать общий результат для списка и выбирать типы аргументов функции шага.

Обработка списка часто сводится к одному правилу. Для пустого списка уже известен результат. Для непустого списка нужно соединить текущий элемент с результатом обработки оставшихся. Свёртка позволяет передать это правило готовой функции вместе с базовым результатом и списком.

## Элемент и результат остатка

У функции шага два аргумента. Первый содержит текущий элемент списка. Второй содержит результат свёртки оставшихся элементов. Возвращаемое значение станет результатом для списка, который начинается с текущего элемента.

Например, программа оценивает общий объём текста в названиях товаров. Для каждого названия нужно прибавить его длину к общему количеству символов остальных названий. Для пустого списка названий это количество равно нулю.

```haskell
addNameLength :: String -> Int -> Int
addNameLength name remainingCount = length name + remainingCount

totalNameLength :: [String] -> Int
totalNameLength names = foldr addNameLength 0 names
```

В этом коде `addNameLength` принимает строку и уже описанный числовой результат для остатка. Выражение `foldr addNameLength 0 names` задаёт шаг, базовый результат `0` и исходный список. Применение `totalNameLength ["Box", "Cable", "Tape"]` даёт `12`, поскольку длины названий равны `3`, `5` и `4`.

Схема раскрывает структуру свёртки этих трёх названий.

```text
foldr addNameLength 0 ["Box", "Cable", "Tape"]
= addNameLength "Box"
    (addNameLength "Cable"
      (addNameLength "Tape" 0))
= 3 + (5 + (4 + 0))
= 12
```

На этой схеме базовый результат расположен в самом вложенном выражении. Каждый шаг получает свой элемент первым аргументом и результат оставшейся части вторым. Скобки вложены вправо. Они показывают связь между выражениями и не задают отдельную инструкцию о порядке выполнения действий.

## Тип свёртки

В этом уроке рассматриваем применение `foldr` к спискам. Соответствующая специализация её типа записывается как `foldr :: (a -> b -> b) -> b -> [a] -> b`. Эта запись описывает именно случай списка, стандартная функция допускает более общее применение.

Переменная `a` задаёт тип исходного элемента. Переменная `b` задаёт тип результата, включая результат пустого списка. Поэтому функция шага получает `a`, затем `b`, и возвращает новый `b`. В примере названия имеют тип `String`, а количество символов имеет тип `Int`.

| Аргумент или результат | Тип в примере |
| --- | --- |
| Текущий элемент | `String` |
| Результат обработки остатка | `Int` |
| Результат шага | `Int` |
| Результат пустого списка | `Int` |

В этой таблице все результаты имеют один тип. Именно поэтому ответ очередного шага может стать вторым аргументом другого шага. Результат всей свёртки тоже имеет этот тип.

Тип результата может отличаться от типа элемента. Например, `b` может обозначать `Integer`, `String` или тип списка `[a]`. Выбор определяется задачей, базовым результатом и функцией шага.

Свёртка не изменяет исходный список. Его можно передать другой функции независимо от того, какой тип выбран для результата `foldr`.

## Базовый результат и порядок

На пустом списке `foldr` возвращает переданный базовый результат без шага. Поэтому `totalNameLength []` даёт `0`. На списке из одного названия получается один шаг, например `addNameLength "Box" 0` с результатом `3`.

Базовый результат не обязан быть нулём. Если к общему объёму названий нужно добавить два служебных символа, можно записать `foldr addNameLength 2 ["Box", "Cable"]`. Результат равен `10`. Для пустого списка в таком варианте результатом останется `2`.

Порядок аргументов шага определяется контрактом `foldr`. Текущий элемент находится слева, а результат оставшейся части справа. Для сложения длин перестановка слагаемых не меняет ответ. На вычитании влияние порядка видно даже при одинаковых типах аргументов. Сравним два правила шага.

```haskell
subtractStep :: Integer -> Integer -> Integer
subtractStep value remaining = value - remaining

subtractReversedStep :: Integer -> Integer -> Integer
subtractReversedStep value remaining = remaining - value
```

Обе функции получают текущий элемент через `value`, а результат остатка через `remaining`. Первая вычитает остаток из элемента. Вторая меняет местами операнды вычитания внутри шага. Следующая развёртка показывает результаты для одного списка и одного базового значения.

```text
foldr subtractStep 0 [10, 3, 2]
= 10 - (3 - (2 - 0))
= 9

foldr subtractReversedStep 0 [10, 3, 2]
= ((0 - 2) - 3) - 10
= -15
```

В первом случае элемент `10` становится левым операндом внешнего вычитания. Во втором случае он оказывается правым операндом. Контракт `foldr` и расположение вложенных вызовов шага сохраняются, но выбранное правило меняет положение операндов и итог вычисления.

При чтении выражения с `foldr` нужно определить базовый результат для пустого списка, правило соединения элемента с результатом остальных и общий тип этих результатов. После этого развёртка нескольких элементов позволяет проверить скобки и положение базового результата.
