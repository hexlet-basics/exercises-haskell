В этом уроке мы изучим параметры типов в сигнатурах Haskell. Разберём, как читать одинаковые и независимые переменные типов. Мы научимся писать общую реализацию для значений разных типов и определять допустимые действия по её сигнатуре.

Некоторые функции перестраивают данные, сохраняя сами значения. Например, функция может поместить одно значение в обе позиции пары. Для такой операции не требуется знать, передана строка, логическое значение или число. В сигнатуре можно выразить эту независимость от конкретного типа.

## Переменная типа

Конкретное имя `String` в сигнатуре задаёт именно строковый тип. Переменная типа, например `a`, обозначает место для типа, который определяется в конкретном применении функции. Переменные типов пишутся со строчной буквы.

Функцию, создающую пару из одного значения, можно определить так.

```haskell
duplicate :: a -> (a, a)
duplicate value = (value, value)
```

В этом коде `a` встречается в типе аргумента и в обеих позициях результата. Все три вхождения обозначают один и тот же тип. Функция `duplicate` подходит для разных типов, поскольку её тело только использует переданное значение при построении пары. Такой способ обобщения называется параметрическим полиморфизмом.

Таблица показывает, как общий тип используется для отдельных применений.

| Выбранный тип `a` | Тип аргумента | Тип результата |
| --- | --- | --- |
| `String` | `String` | `(String, String)` |
| `Integer` | `Integer` | `(Integer, Integer)` |
| `Bool` | `Bool` | `(Bool, Bool)` |

В этой таблице тип в каждой строке подставлен во все позиции `a` одновременно. Например, `duplicate "Cedar"` даёт `("Cedar", "Cedar")`, а `duplicate True` даёт `(True, True)`. Для этих применений используется одно определение функции.

Буква `a` находится в сигнатуре, а имя `value` в определении обозначает само переданное значение. Это разные роли. Типы проверяет компилятор, и для каждого применения он согласует фактический тип аргумента с сигнатурой.

## Одинаковые имена типов

Повторение переменной типа задаёт связь между частями сигнатуры. Например, контракт функции может требовать два аргумента одного типа и возвращать первый из них.

```haskell
chooseFirst :: a -> a -> a
chooseFirst first _ = first
```

В этом коде оба аргумента имеют тип `a`. Они могут содержать разные значения, например строки `"North"` и `"South"`. Применение `chooseFirst "North" "South"` даёт `"North"`. С тем же контрактом допустимо `chooseFirst True False`, результатом которого будет `True`. Знак `_` в определении `chooseFirst` означает, что значение второго аргумента в результате не используется.

Смешать строку и логическое значение в одном таком применении не получится. Для `chooseFirst "North" True` компилятор не может выбрать один тип `a`, подходящий обоим аргументам. Ошибка следует из указанного контракта функции.

## Независимые параметры типов

Разные переменные позволяют независимо выбрать типы аргументов. Например, функция может собрать полученные значения в одну пару.

```haskell
keepInputs :: a -> b -> (a, b)
keepInputs first second = (first, second)
```

В этом коде `a` относится к первому аргументу и первой позиции результата. Переменная `b` связывает второй аргумент со второй позицией. Поэтому `keepInputs "Cedar" True` возвращает `("Cedar", True)`. Здесь `a` выбран как `String`, а `b` как `Bool`.

Разные имена не требуют разных типов. Применение `keepInputs True False` тоже допустимо, и результат равен `(True, False)`. В этом случае обе независимые переменные обозначают `Bool`.

Полные сигнатуры знакомых операций с парами читаются по тому же принципу. У `fst` тип `(a, b) -> a`, а у `snd` тип `(a, b) -> b`. Буквы показывают, из какой позиции берётся результат.

## Действия над неизвестным типом

Сигнатура с произвольным `a` требует реализации, подходящей для любого выбранного типа. Можно передавать значение дальше, возвращать его, помещать в пару или список. Сами эти действия не требуют знания его внутреннего устройства.

Возможность складывать числа или сравнивать значения пока из такого контракта не следует. Например, выражение `value + value` нельзя использовать как общий способ обработки аргумента неизвестного типа. Строка и логическое значение не поддерживают используемое здесь сложение. Общая функция сохраняет только те предположения, которые выражены её сигнатурой.
