В этом уроке мы изучим каррирование и частичное применение функций Haskell. Разберём цепочку функций с одним аргументом и чтение сигнатур с несколькими стрелками. Мы научимся получать функцию с фиксированным аргументом и использовать её в дальнейших вычислениях.

Функция может возвращать другую функцию. Это позволяет разделить получение нескольких аргументов на последовательные применения. После первого применения результатом становится функция, которой доступно переданное значение. Она принимает следующий аргумент и продолжает вычисление. Такое представление функции с несколькими аргументами называется каррированием.

## Последовательное применение

Например, программа формирует подпись предмета из категории и названия. Оба значения являются строками, и подпись соединяет их с разделителем.

```haskell
labelWith :: String -> String -> String
labelWith category item = category ++ ": " ++ item
```

В этом коде `labelWith "Book" "Haskell"` даёт строку `"Book: Haskell"`. Запись с двумя аргументами читается как `(labelWith "Book") "Haskell"`. Сначала мы рассматриваем применение `labelWith` к категории. Его результат применяется к названию предмета.

Значение `labelWith "Book"` является функцией типа `String -> String`. Ей уже доступна категория `"Book"`, и для готовой подписи ей требуется название. Схема показывает тип промежуточного результата.

```text
labelWith
    |
    | "Book"
    v
функция String -> String
    |
    | "Haskell"
    v
"Book: Haskell"
```

В этой схеме первое применение даёт функцию, а второе строку. Между ними получается обычное значение функции, которое можно сохранить под именем или передать дальше. Готовой подписи на промежуточном этапе ещё нет.

## Как группируются стрелки

Сигнатура `String -> String -> String` означает `String -> (String -> String)`. Первая стрелка связывает тип первого аргумента с типом результата, которым здесь является функция. У этой возвращаемой функции есть собственный аргумент `String` и собственный результат `String`.

Общее правило для сигнатуры `a -> b -> c` даёт группировку `a -> (b -> c)`. Стрелки группируются вправо. У применения функции группировка обратная, выражение `f x y` означает `(f x) y`. Скобки в этих двух записях выполняют разные задачи, одна запись описывает тип, другая применение значения.

Это правило объясняет и возврат функции через лямбду. Определение `labelWith` можно записать в следующей эквивалентной форме.

```haskell
labelWith :: String -> (String -> String)
labelWith category = \item -> category ++ ": " ++ item
```

В этом коде функция принимает `category` и возвращает лямбду. Возвращённая функция получает `item`, используя сохранённое имя `category` из окружающей области. Обе записи определения дают одинаковые подписи для одинаковых аргументов.

Скобки с запятой имеют другой смысл. Они объединяют значения в пару, которая становится одним аргументом. Следующее определение намеренно передаёт такую пару функции `labelWith`.

<!-- lint-code-blocks: skip — намеренно передана пара вместо строкового аргумента -->
```text
brokenLabel = labelWith ("Book", "Haskell")
```

При проверке этого определения GHC сообщает о несовместимости. Ключевые строки сообщения выглядят так.

```text
    • Couldn't match type: (String, String)
                     with: [Char]
      Expected: String
        Actual: (String, String)
```

В сообщении `Expected: String` указывает ожидаемый тип первого аргумента `labelWith`. Строка `Actual: (String, String)` показывает фактически переданную пару. Запись `[Char]` обозначает тот же строковый тип, что и `String`. Для двух отдельных аргументов подходит применение `labelWith "Book" "Haskell"`, в котором строки записаны через пробел.

## Фиксация первого аргумента

Частичное применение использует каррированную структуру. Мы передаём часть аргументов и получаем функцию для оставшихся аргументов. Например, всем подписям книг нужна одна и та же категория.

```haskell
bookLabel :: String -> String
bookLabel = labelWith "Book"
```

В этом коде имя `bookLabel` связано со значением функции `labelWith "Book"`. Тип `String -> String` показывает, какой аргумент ещё требуется. В левой части определения нет имени для этого аргумента, поскольку правая часть уже является нужной функцией.

Применение `bookLabel "Haskell"` даёт `"Book: Haskell"`, а `bookLabel "Types"` даёт `"Book: Types"`. Категория остаётся фиксированной, а название можно передавать многократно. Само создание `bookLabel` не требует заранее знать все будущие названия.

Можно сопоставить это определение с явной лямбдой.

```haskell
bookLabel :: String -> String
bookLabel = \item -> labelWith "Book" item
```

В этом коде лямбда явно показывает оставшийся аргумент. При частичном применении ту же функцию даёт выражение `labelWith "Book"`. Каррирование описывает устройство цепочки функций, а частичное применение использует её для фиксации части аргументов.
