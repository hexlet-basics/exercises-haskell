В этом уроке мы изучим выражения и неизменяемые имена в Haskell. Разберём, как связывать имя с вычислением и использовать его в других определениях. Мы научимся собирать строковый результат из именованных частей и читать зависимости между ними.

Когда один фрагмент текста нужен в нескольких местах, ему удобно дать имя. Тогда выражение с этим именем описывает, какое значение участвует в вычислении. Выражением может быть строка в кавычках, применение функции или соединение других выражений через `++`.

## Имена для частей результата

Определение связывает имя слева от `=` с выражением справа. Имена значений и функций начинаются со строчной буквы. Имена типов и конструкторов начинаются с заглавной буквы, их устройство мы разберём дальше по курсу. В других выражениях можно использовать само имя, сохранив смысл связанного с ним значения.

Например, программа формирует подпись переговорной комнаты. Помещение находится в восточном корпусе, а его название должно появиться на карточке дважды. Общую часть подписи можно определить отдельно.

```haskell
building = "East"
room = "Cedar"
address = building ++ " / " ++ room
card = address ++ " | " ++ address
```

В этом коде `building` связано со строкой `"East"`, а `room` со строкой `"Cedar"`. Выражение для `address` соединяет эти значения с разделителем и даёт `"East / Cedar"`. Имя `address` используется в определении `card` дважды, поэтому результат равен `"East / Cedar | East / Cedar"`.

Чтобы понять зависимости, достаточно проследить имена в правой части каждого определения. Схема показывает, какие значения нужны для получения карточки.

```text
building      room
     \        /
       address
          |
         card
```

В этой схеме `address` зависит от `building` и `room`, а `card` от `address`. Соединение строк образует новое значение. Исходные строки сохраняются, и их можно использовать в других выражениях.

## Неизменяемое определение

Областью видимости называется часть программы, в которой доступно данное имя. В одном наборе определений имя обозначает одно значение. Если нам нужны две разные подписи, мы даём им разные имена и используем каждую по назначению. Второе определение того же имени в одной области видимости приводит к ошибке, программа с ним не компилируется.

Например, этот фрагмент содержит ошибку.

<!-- lint-code-blocks: skip — повторное определение одного имени намеренно неверно -->

```text
room = "Cedar"
room = "Maple"
```

Здесь объявлены два определения `room` в одной области видимости, поэтому компилятор сообщает о повторном объявлении. Для отдельного помещения подойдёт новое имя, например `otherRoom`.

Компилятор показывает ключевую строку сообщения.

```text
Multiple declarations of ‘room’
```

В этой строке компилятор называет имя `room`, которое определено повторно. Правка должна оставить одно определение в этой области видимости.

Порядок определений в таком файле не задаёт последовательность изменения значений. Например, определение `card` можно поместить перед именами, от которых оно зависит.

```haskell
card = address ++ " | " ++ address
address = building ++ " / " ++ room
room = "Cedar"
building = "East"
```

В этом коде зависимости остаются прежними, поэтому `card` имеет то же значение. Мы читаем определения как описание связей между выражениями. Указывать имена рядом с их использованием всё равно полезно для читателя программы.

## Комментарии и расположение кода

Короткий комментарий начинается с `--` и продолжается до конца строки. Он помогает пояснить назначение определения. Например, перед общей подписью комнаты можно оставить такой комментарий.

```haskell
-- Shared room label
address = building ++ " / " ++ room
```

В этом фрагменте комментарий не участвует в вычислении `address`. Он объясняет назначение подписи человеку, который читает код.

Самостоятельные определения на уровне файла располагаются с одинаковым отступом. В показанных примерах они начинаются с первой колонки. Продолжение определения на следующей строке начинается правее его начала. Такой отступ показывает, к какому определению относится выражение. Например, подпись можно записать в несколько строк.

```haskell
address =
  building ++ " / " ++ room
```

В этом коде строка с `building` продолжает определение `address`. Если убрать отступ, компилятор попытается разобрать её как новое определение и отклонит фрагмент.

<!-- lint-code-blocks: skip — продолжение определения намеренно оставлено без отступа -->

```text
address =
building ++ " / " ++ room
```

В этом фрагменте отсутствует необходимый отступ перед `building`. Пустая строка между отдельными определениями на отступы не влияет.

При таком расположении строк компилятор отвечает сообщением об ошибке разбора.

```text
parse error (possibly incorrect indentation or mismatched brackets)
```

В сообщении компилятор предлагает проверить отступы и скобки. Здесь причина в первой колонке у продолжения определения.

## Имена внутри функции

Именованные значения можно использовать и в теле функции. Если название комнаты поступает как аргумент, функция собирает подпись для каждого полученного названия.

```haskell
building = "East"

describeRoom :: String -> String
describeRoom name = building ++ " / " ++ name
```

В этом коде `describeRoom "Maple"` даёт `"East / Maple"`, а `building` сохраняет значение `"East"`. Имя аргумента `name` получает значение для конкретного применения функции. Благодаря общему имени корпуса его строка одинаково используется для разных названий комнат.
