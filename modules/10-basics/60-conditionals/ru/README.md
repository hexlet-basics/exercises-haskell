В этом уроке мы изучим логические и условные выражения в Haskell. Разберём сравнения, объединение условий и выбор результата через `if then else`. Мы научимся описывать ветвление внутри чистой функции и согласовывать типы его ветвей.

Чтобы вычисление зависело от входных данных, нам нужно описать проверку и результаты для её исходов. Проверка даёт логическое значение типа `Bool`. У этого типа есть два значения, `True` и `False`, которые пишутся с заглавной буквы.

## Логические значения

Сравнение двух чисел тоже является выражением. Например, проверка `12 > 5` даёт `True`, а `12 == 5` даёт `False`. Результат можно передать функции или использовать как условие выбора. Один знак `=` остаётся знаком определения имени, а равенство проверяется через `==`.

Операторы сравнения над числами имеют привычный смысл.

| Оператор | Проверка |
| --- | --- |
| `==` | Значения равны |
| `/=` | Значения различаются |
| `<` | Левое значение меньше правого |
| `<=` | Левое значение меньше правого или равно ему |
| `>` | Левое значение больше правого |
| `>=` | Левое значение больше правого или равно ему |

Здесь оба операнда сравнения являются числами, а результат имеет тип `Bool`. Можно составить несколько проверок и соединить их логическими операциями. Оператор `&&` требует истинности обеих проверок, `||` допускает хотя бы одну истинную проверку, а функция `not` меняет `True` на `False` и наоборот.

Например, программа допускает посетителя на мероприятие, если ему уже исполнилось 18 лет и у него есть приглашение. Функция получает возраст и готовое логическое значение о наличии приглашения.

```haskell
canEnter :: Integer -> Bool -> Bool
canEnter age hasInvitation = age >= 18 && hasInvitation
```

В этой функции `age >= 18` проверяет возраст. Всё выражение даёт `True`, только когда проверка возраста и аргумент `hasInvitation` истинны. Применение `canEnter 20 True` даёт `True`, а `canEnter 20 False` и `canEnter 17 True` дают `False`.

Выражение `not (canEnter 20 False)` даёт `True`. Так мы можем получить обратный результат готовой проверки. Если правило допускает любой из двух вариантов, их соединяют через `||`, например `age < 18 || age >= 65`. При сочетании нескольких операций скобки помогают явно выделить нужные группы проверок.

## Выбор значения

Условное выражение записывается через `if`, `then` и `else`. После `if` стоит значение типа `Bool`. Ветвь после `then` задаёт результат для `True`, а ветвь после `else` задаёт результат для `False`.

Схема показывает выбор одной из двух ветвей по значению условия.

```text
              Условие :: Bool
              /             \
           True             False
             |                |
      Выражение then   Выражение else
```

На этой схеме истинное условие ведёт к ветви `then`, а ложное к ветви `else`. Значение выбранной ветви становится результатом всего условного выражения.

Допустим, участнику нужно показать подпись состояния допуска. Функция может использовать готовую проверку и вернуть одну из двух строк.

```haskell
entryLabel :: Integer -> Bool -> String
entryLabel age hasInvitation =
  if canEnter age hasInvitation
    then "Allowed"
    else "Not allowed"
```

В этом коде `entryLabel 20 True` возвращает `"Allowed"`. Для `entryLabel 17 True` результатом будет `"Not allowed"`. Само выражение `if` имеет тип `String`, поскольку обе ветви возвращают строки. Его результат становится результатом функции.

Ветвь `else` обязательна. У выражения должен быть результат при каждом исходе проверки. По этой же причине обе ветви должны иметь одинаковый тип. Следующее определение содержит ошибку типов.

<!-- lint-code-blocks: skip — ветви намеренно возвращают несовместимые типы -->

```text
wrong :: Integer -> Integer
wrong amount = if amount > 0 then amount else "empty"
```

В этом примере `amount` имеет тип `Integer`, а `"empty"` имеет тип `String`. Компилятор не может согласовать их как один результат условного выражения.

Компилятор показывает типы несовместимых ветвей.

```text
Couldn't match type ‘[Char]’ with ‘Integer’
Expected: Integer
  Actual: String
```

В сообщении ожидаемый `Integer` сопоставлен со строкой. Обе ветви условного выражения должны давать один тип результата.

## Короткое замыкание

Операторы `&&` и `||` проверяют левую часть прежде правой. Если слева от `&&` получено `False`, всё выражение уже ложно. Если слева от `||` получено `True`, всё выражение уже истинно. В этих случаях правую часть вычислять не нужно.

Например, проверка может защитить деление от нулевого делителя.

```haskell
hasLargeShare :: Integer -> Bool
hasLargeShare count = count /= 0 && div 100 count > 20
```

В этой функции при `count`, равном нулю, сравнение `count /= 0` даёт `False`. Поэтому деление не выполняется и результат всей проверки равен `False`. Для `count`, равного двум, деление даёт `50` и вся проверка возвращает `True`. Порядок частей условия здесь существенен, проверка делителя стоит перед выражением с делением.
