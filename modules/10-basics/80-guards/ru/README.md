В этом уроке мы изучим охранные условия в определениях функций Haskell. Разберём выбор ветви по нескольким проверкам и влияние их порядка на результат. Мы научимся покрывать допустимые входные данные и использовать завершающую ветвь `otherwise`.

Когда у вычисления несколько вариантов результата, каждому варианту можно сопоставить логическую проверку. Охранные условия позволяют записать эти проверки рядом с определением функции. Каждая ветвь содержит условие типа `Bool` и выражение результата.

Проверки просматриваются сверху вниз. Первая проверка, давшая `True`, выбирает результат функции для переданных аргументов. К следующим ветвям после этого переходить не нужно. Схема показывает последовательность выбора.

```text
Условие первой ветви  -- True --> Первый результат
        |
      False
        |
Условие второй ветви  -- True --> Второй результат
        |
      False
        |
Завершающая ветвь     ----------> Остальной результат
```

В этой схеме каждая ложная проверка передаёт выбор ниже. Истинная проверка завершает поиск подходящей ветви. Благодаря этому несколько условий могут подходить одному входу, если порядок выражает нужный приоритет.

## Запись ветвей функции

Например, музей рассчитывает стоимость билета в рублях. Владелец пропуска проходит бесплатно, ребёнок младше 12 лет платит 400 рублей, посетитель от 65 лет платит 500 рублей. Для остальных посетителей билет стоит 800 рублей. Возраст поступает как неотрицательное целое число, а наличие пропуска задаётся значением `Bool`.

```haskell
ticketPrice :: Integer -> Bool -> Integer
ticketPrice age hasPass
  | hasPass = 0
  | age < 12 = 400
  | age >= 65 = 500
  | otherwise = 800
```

В этом коде после имени функции и аргументов записаны отдельные ветви. Вертикальная черта `|` начинает ветвь, после неё стоит логическое условие. Знак `=` отделяет условие от выражения результата. Все ветви возвращают `Integer`, что согласуется с сигнатурой функции.

Для `ticketPrice 10 False` первая проверка ложна, а `age < 12` истинна, поэтому результат равен `400`. Применение `ticketPrice 70 False` даёт `500`. Для `ticketPrice 30 False` выбирается последняя ветвь, и функция возвращает `800`.

Каждая вертикальная черта расположена с одинаковым отступом. Строки ветвей начинаются с отступом относительно имени функции, поэтому компилятор относит их к тому же определению. Эти отступы помогают увидеть, какие ветви принадлежат одному определению.

## Приоритет проверок

Условия могут пересекаться. Например, ребёнок тоже может владеть пропуском. Для `ticketPrice 10 True` подходят проверки `hasPass` и `age < 12`, но результат равен `0`, поскольку проверка пропуска стоит первой.

Если поменять эти две ветви местами, изменится правило расчёта. Следующий фрагмент показывает ошибку в реализации описанного тарифа.

<!-- lint-code-blocks: skip — неверный порядок ветвей нарушает правило бесплатного входа -->

```text
ticketPrice age hasPass
  | age < 12 = 400
  | hasPass = 0
  | age >= 65 = 500
  | otherwise = 800
```

В этом фрагменте `ticketPrice 10 True` уже даёт `400`. Условие возраста срабатывает до проверки пропуска. Такой результат нарушает правило бесплатного входа по пропуску. Порядок ветвей должен отражать приоритет правил предметной задачи.

## Завершающая ветвь

Имя `otherwise` обозначает стандартное значение `True`. В последней ветви оно подходит любому входу, который дошёл до неё. В примере с билетами эта ветвь задаёт обычную цену для всех оставшихся посетителей.

Если поместить `otherwise` первой, она выберет результат для каждого входа. Остальные проверки станут недостижимыми. Поэтому общий случай записывается после более конкретных правил.

Функция должна давать результат для любого входа, разрешённого её условием использования. Если все охранные условия ложны и подходящей ветви больше нет, вычисление завершается ошибкой. Например, без последней ветви функция стоимости не смогла бы обработать посетителя 30 лет без пропуска.

Полноту удобно проверять по границам диапазонов. В примере важны возраст `11` и `12`, а также `64` и `65`. Для каждой такой пары видно, к какой ветви относится сама граница и соседнее значение. Отдельная проверка посетителя с пропуском подтверждает приоритет первого правила.
