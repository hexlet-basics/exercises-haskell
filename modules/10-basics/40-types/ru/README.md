В этом уроке мы изучим сигнатуры и вывод типов в Haskell. Разберём основные типы значений и запись типов аргументов и результата функции. Мы научимся задавать конкретные сигнатуры и находить несовместимость между объявленным типом и выражением.

## Тип значения

Тип определяет, какие значения допустимы в данном месте программы. Например, текстовое имя устройства, его температура и признак готовности представляют разные данные. Когда программа передаёт значение функции, тип аргумента должен подходить типу её входа.

Haskell проверяет эту совместимость до выполнения программы. Такой подход называется статической типизацией. Ошибка типов требует исправить определение или применение функции, прежде чем удастся запустить программу.

Написание имени помогает человеку понять назначение данных. Например, слово `ready` в имени не сообщает компилятору тип значения. Компилятор определяет тип по выражению, его использованию и написанной сигнатуре.

Сигнатура позволяет явно назвать тип определения. Предположим, система хранит название переговорной комнаты. Его значение и тип можно записать так.

```haskell
roomName :: String
roomName = "Maple"
```

В этом коде `::` связывает имя `roomName` с типом `String`. Строка с `=` задаёт значение этого имени. Сигнатура и определение относятся к одному и тому же `roomName`. У них разные задачи, поэтому знак `::` не заменяет `=`.

Основные типы для небольших программ перечислены в таблице. Примеры в ней показывают значения с явно выбранным типом.

| Тип | Какие значения представляет | Пример |
| --- | --- | --- |
| `Integer` | Целые числа произвольной точности | `12345678901234567890` |
| `Int` | Целые числа в ограниченном диапазоне | `8` |
| `Double` | Числа с плавающей точкой | `21.5` |
| `Bool` | Логические значения | `True`, `False` |
| `Char` | Отдельный символ | `'C'` |
| `String` | Строку символов | `"Celsius"` |

Для `Integer` размер числа может увеличиваться, пока хватает памяти. У `Int` есть нижняя и верхняя границы, зависящие от платформы. Поэтому для произвольно большого целого выбираем `Integer`. Тип `Double` подходит для многих измерений, но дробные значения в нём могут храниться приближённо.

У значений `Bool` первая буква заглавная. Кавычки превратили бы `"True"` в строку. Одинарные кавычки обозначают `Char`, а двойные обозначают `String`. Поэтому `'C'` и `"C"` имеют разные типы, хотя при чтении человеком выглядят похоже.

## Тип функции

Тип функции связывает входные значения с результатом вычисления. Для одного аргумента слева от стрелки пишется его тип, справа пишется тип результата. Посмотрим на функцию, которая добавляет завершающий фрагмент к переданному тексту.

```haskell
attach :: String -> String -> String
attach text ending = text ++ ending
```

В этом коде `attach` получает два аргумента. Первая запись `String` соответствует `text`, вторая соответствует `ending`, последняя обозначает тип результата. Между аргументами в определении стоят пробелы. Например, выражение `attach "Maple" "!"` даёт строку `"Maple!"`. Способ чтения нескольких стрелок мы подробнее разберём при изучении каррирования.

Типы разных аргументов могут отличаться. Сигнатура `String -> Integer -> String` описывает применение к строке и целому числу с получением строки. При чтении конкретной сигнатуры важно учитывать порядок аргументов. Перестановка входов меняет требования к применению функции.

## Вывод типов и ошибки

Haskell умеет устанавливать типы по выражениям и их использованию. Это называется выводом типов. Например, из строкового литерала `"Maple"` компилятор определит тип `roomName` даже без написанной сигнатуры. Для числовых литералов подходят разные числовые типы, поэтому явная сигнатура помогает закрепить нужный выбор.

Записанная сигнатура проверяется на совместимость с определением. Если мы объявили логическое значение, текстовая запись этого значения не подойдёт. Следующий фрагмент намеренно содержит ошибку.

<!-- lint-code-blocks: skip — намеренно несовместимые типы Bool и String -->
```text
ready :: Bool
ready = "True"
```

В этом примере сигнатура требует `Bool`, а выражение справа от `=` имеет тип `String`. Компилятор сообщает о несовместимости. Чтобы получить логическое значение, в определении нужна запись `True` без кавычек. Если же нам требовался текст, подходящей сигнатурой будет `String`.

Компилятор показывает несовместимые типы.

```text
Couldn't match type ‘[Char]’ with ‘Bool’
Expected: Bool
  Actual: String
```

В сообщении `Expected` называет ожидаемый тип `Bool`, а `Actual` показывает фактический тип строки. Запись `[Char]` обозначает `String`, связь со списком символов мы разберём отдельно.

Такая проверка помогает заметить перепутанные представления данных до запуска. При этом одна сигнатура не описывает все предметные ограничения. Например, `Integer` допускает и отрицательные значения. Количество полученных датчиком измерений должно быть неотрицательным. Это правило потребуется проверять в самой функции при знакомстве с условиями.
