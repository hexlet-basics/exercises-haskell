В каркасе уже записаны определения данных температурного датчика. Допишите перед каждым определением явную сигнатуру. Выберите тип по назначению данных и требованиям к их представлению.

- `sampleCount` содержит `987654321098765432109876543210` полученных измерений. Число измерений может превышать диапазон машинного целого, поэтому его нужно хранить целиком без ограничения разрядности.
- `channelCount` содержит `6` подключённых каналов. Для этого поля используется машинное целое с ограниченным диапазоном.
- `referenceTemperature` содержит температуру `64.25` в числовом типе с плавающей точкой двойной точности.
- `deviceReady` содержит признак готовности. Датчик ещё не готов, поэтому его значение равно `False`.
- `unitCode` содержит один символ единицы измерения `'F'`.
- `deviceName` содержит текстовое название `"Thermal probe"`.

Для `deviceReady` и `unitCode` в английских комментариях оставлены неверные черновые сигнатуры. Сопоставьте их с готовыми определениями, найдите несовместимость и впишите правильные сигнатуры в соответствующие пустые области. Комментарии с черновиками сами по себе не задают тип.

Также допишите сигнатуру `makeLabel`. Тело функции уже дано. Первый аргумент содержит текстовый код помещения, второй текстовое имя датчика. Результатом является строка, которая соединяет оба аргумента разделителем `" / "`.

Примеры показывают поведение готового тела функции.

```haskell
makeLabel "D4" "Thermal probe" -- "D4 / Thermal probe"
makeLabel "C8" "Auxiliary"     -- "C8 / Auxiliary"
makeLabel "" "Probe"           -- " / Probe"
```

Оба аргумента могут быть пустыми. Функция сохраняет все переданные символы, включая регистр и пробелы.

Изменять готовые значения и тело `makeLabel` не нужно. В каждой области между маркерами записывается только сигнатура того определения, которое расположено сразу под ней. Определения остаются в модуле `Solution`. Вывод на экран не требуется.
