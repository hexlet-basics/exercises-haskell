В этом уроке мы изучим представление отсутствующего значения через `Maybe`. Разберём конструкторы `Just` и `Nothing` и обработку обоих вариантов. Мы научимся безопасно извлекать данные и передавать отсутствие результата дальше по вычислению.

Функция извлечения первого элемента списка может получить пустой список. Для такого входа первого элемента нет. Если результат имеет обычный тип элемента, например `Integer`, придётся заранее выбрать какое-то число для этого случая. Но то же число может оказаться настоящим элементом списка. Тип `Maybe` позволяет явно различить найденное значение и его отсутствие.

## Два варианта результата

Стандартный тип `Maybe a` содержит параметр типа `a`. Конструктор `Just` хранит одно значение этого типа. Конструктор `Nothing` обозначает отсутствие значения и не хранит содержимого. Тип и оба конструктора доступны в обычном файле Haskell без дополнительного импорта.

Схема показывает варианты готового типа.

```text
Maybe a
  +-- Nothing
  +-- Just value
           |
           value :: a
```

На этой схеме `a` обозначает тип возможного содержимого. Вариант `Just` даёт доступ к этому содержимому после разбора. В варианте `Nothing` извлекать нечего, поэтому функция обработки описывает для него отдельное действие.

Например, при выборе `a` как `Integer` возможны значения `Just 0`, `Just 15` и `Nothing`. Ноль внутри `Just` является обычным найденным числом. У `Maybe String` найденный текст записывается через `Just "Ready"`, а отсутствие текста через `Nothing`. Пустая строка `Just ""` тоже отличается от отсутствия строки.

## Безопасное извлечение

Функция может возвращать первый элемент любого списка через `Maybe`. Для пустого случая она создаёт `Nothing`. Для непустого случая она помещает первый элемент в `Just`.

```haskell
firstValue :: [a] -> Maybe a
firstValue [] = Nothing
firstValue (value : _) = Just value
```

В этом коде `firstValue [0, 12]` даёт `Just 0`, а `firstValue ["Ready", "Waiting"]` даёт `Just "Ready"`. Для пустого списка результатом будет `Nothing`. Все элементы допустимого входа обрабатываются без обращения к отсутствующему первому элементу.

Переменная типа `a` связывает элемент исходного списка с содержимым результата. Функция только извлекает значение и строит вариант, поэтому от содержимого не требуется арифметика или сравнение. Та же реализация подходит для чисел, строк и других типов.

## Обработка результата через case

Получатель результата должен решить, что делать в обоих случаях. Через `case` можно отдельно описать отсутствие и успешное извлечение. Например, приложение показывает первую заметку или сообщение о том, что заметок пока нет.

```haskell
firstNote :: [String] -> String
firstNote notes =
  case firstValue notes of
    Nothing -> "No notes"
    Just text -> "Note: " ++ text
```

В этой функции `Nothing` приводит к строке `"No notes"`. Ветвь `Just text` извлекает найденную строку под именем `text`. Для `firstNote ["Check cable"]` результат равен `"Note: Check cable"`. Для `firstNote [""]` получится `"Note: "`, поскольку заметка существует и содержит пустой текст.

Обе ветви возвращают `String`, поэтому такой тип имеет всё выражение `case`. Сама функция `firstValue` не выбирает сообщение для пользователя. Этот выбор находится в функции `firstNote`, которая знает назначение полученного результата.

## Сохранение отсутствия

Иногда следующий шаг вычисления тоже может не дать значения. Тогда результат можно оставить в `Maybe`, обработав оба варианта явно. Например, функция вычисляет длину первой заметки, если заметка есть.

```haskell
firstNoteLength :: [String] -> Maybe Int
firstNoteLength notes =
  case firstValue notes of
    Nothing -> Nothing
    Just text -> Just (length text)
```

В этом коде отсутствие первой заметки сохраняется как `Nothing`. При наличии заметки её длина помещается в `Just`. Поэтому `firstNoteLength ["Ready"]` даёт `Just 5`, `firstNoteLength [""]` даёт `Just 0`, а пустому списку соответствует `Nothing`.

У значения `Maybe a` есть ровно два объявленных варианта, и полный `case` обрабатывает оба. Если оставить только ветвь `Just`, вызов на `Nothing` завершится ошибкой во время вычисления. Следующий пример намеренно содержит такой неполный разбор.

<!-- lint-code-blocks: skip — сознательно неполный case для демонстрации ошибки на Nothing -->
```text
incompleteNote :: Maybe String -> String
incompleteNote note =
  case note of
    Just text -> "Note: " ++ text
```

Это определение принимается компилятором, но при вычислении `incompleteNote Nothing` подходящей ветви нет. В GHC 9.0.2 ключевой фрагмент фактического сообщения об ошибке выглядит так.

```text
Non-exhaustive patterns in case
```

Сообщение указывает, что образцы в `case` не покрывают полученное значение. В функции `firstNote` такой вход обрабатывает ветвь `Nothing`, которая возвращает `"No notes"`. Полный разбор позволяет заранее определить результат и для найденного значения, и для его отсутствия.
