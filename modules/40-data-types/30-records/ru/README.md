В этом уроке мы изучим типы с именованными полями в Haskell. Разберём создание записи, чтение её полей и получение нового значения с обновлённым полем. Мы научимся сохранять остальные данные записи и проверять исходное значение после преобразования.

Программа хранит название устройства и процент оставшегося заряда. Позиционный конструктор может объединить эти данные, но при чтении или замене одной части приходится учитывать расположение остальных. Например, функция переименования сохраняет заряд через сопоставление с образцом.

```haskell
data PlainDevice = PlainDevice String Integer

renamePlainDevice :: PlainDevice -> String -> PlainDevice
renamePlainDevice (PlainDevice _ charge) newName =
  PlainDevice newName charge
```

В этой функции образец извлекает заряд, чтобы передать его конструктору вместе с новым названием. При работе с `PlainDevice "Reader" 80` назначение числа `80` приходится помнить из порядка аргументов. Именованные поля позволяют указать роль каждой части прямо в объявлении типа, читать её по имени и обновлять отдельно от остальных.

## Объявление записи

Те же данные устройства можно описать с именами полей. У типа есть один конструктор, который объединяет название и заряд.

```haskell
data Device = Device
  { deviceName :: String
  , batteryPercent :: Integer
  }
```

В этом коде `Device` слева от `=` является именем типа, а справа именем конструктора значения. В фигурных скобках объявлены поля `deviceName` и `batteryPercent`. Возле каждого поля указан тип его содержимого. Такая форма объявления называется записью.

Для создания устройства можно передать конструктору значения по именам полей.

```haskell
reader :: Device
reader = Device {deviceName = "Reader", batteryPercent = 80}
```

В этом коде `reader` имеет тип `Device`. Его название равно `"Reader"`, а заряд равен `80`. Имя каждого поля связывает переданное значение с нужной частью устройства. Порядок полей в фигурных скобках при создании может быть любым.

Имена полей должны быть объявлены у используемого конструктора, а их значения должны соответствовать указанным типам.

## Чтение полей

Объявление записи создаёт функции для получения её полей. В нашем примере `deviceName` имеет тип `Device -> String`, а `batteryPercent` тип `Device -> Integer`. Каждая функция принимает целое описание устройства и возвращает одну его часть.

Например, из `reader` можно получить подпись и текущий заряд.

```haskell
readerLabel :: String
readerLabel = deviceName reader

readerCharge :: Integer
readerCharge = batteryPercent reader
```

В этом коде `readerLabel` равно `"Reader"`, а `readerCharge` равно `80`. Вызов поля записывается как обычное применение функции. `deviceName` извлекает название, а `batteryPercent` заряд из того же значения `reader`.

Конструктор также сохраняет возможность позиционной записи. Выражение `Device "Reader" 80` создаёт то же описание устройства. Имена полей удобны, когда важно видеть роль каждого передаваемого значения прямо в записи создания.

## Обновление как новое значение

Готовое устройство может получить другое название в новой версии данных. Для этого перед фигурными скобками записывается исходное значение, а внутри указываются поля, которые должны получить новые значения.

```haskell
renamedReader :: Device
renamedReader = reader {deviceName = "Display"}
```

В этом коде `reader` служит исходным описанием. Выражение создаёт новое значение `renamedReader`, в котором название равно `"Display"`. Поле `batteryPercent` сохраняет значение `80`, поскольку обновление его не меняет.

Таблица показывает связь исходных и полученных данных.

| Поле | Исходное устройство | Полученное устройство |
| --- | --- | --- |
| `deviceName` | `"Reader"` | `"Display"` |
| `batteryPercent` | `80` | `80` |

В этой таблице новое название появляется только в полученном устройстве. Применение `deviceName reader` по-прежнему даёт `"Reader"`. Выражение обновления сохраняет доступность исходного значения и позволяет использовать обе версии в разных вычислениях.

Новое значение поля может зависеть от текущих данных. Например, после работы устройства нужно уменьшить его заряд на израсходованное количество процентных пунктов. В этом примере расход находится между нулём и исходным зарядом.

```haskell
drainBattery :: Device -> Integer -> Device
drainBattery device used =
  device {batteryPercent = batteryPercent device - used}
```

В этой функции `batteryPercent device` читает исходный заряд. Вычитание `used` вычисляет новый заряд, а обновление записи сохраняет его в результате. При применении `drainBattery reader 12` заряд результата равен `68`, а название остаётся `"Reader"`. У исходного `reader` заряд по-прежнему равен `80`.

В обновлении можно указать несколько полей через запятую. Каждое указанное поле получит новое значение, остальные сохранятся из исходной записи. Для создания с нуля перед скобками стоит имя конструктора, а для обновления имя или выражение уже имеющегося значения.
