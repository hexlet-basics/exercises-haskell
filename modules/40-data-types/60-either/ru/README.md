В этом уроке мы изучим представление ожидаемого отказа с причиной через `Either`. Разберём конструкторы `Left` и `Right`, а также типы данных внутри каждого варианта. Мы научимся возвращать результат проверки и полностью обрабатывать оба её исхода через `case`.

Проверка входных данных может завершиться отказом по правилам задачи. Вызывающей функции при этом полезно получить объяснение, чтобы выбрать дальнейшее действие или сформировать сообщение. Причину можно вернуть как обычное значение вместе с явным обозначением исхода проверки.

Например, проверка количества может отклонить отрицательное число или число выше допустимого предела. Результат `Maybe Integer` свёл бы обе причины к одному `Nothing`. Когда вызывающему коду нужно различить эти случаи, вместе с отказом мы сохраняем его причину.

## Два варианта результата

Тип `Either e a` описывает два варианта значения. Конструктор `Left` содержит значение типа `e`, а `Right` значение типа `a`. При обработке ожидаемых отказов принято помещать в `Left` причину отказа, а в `Right` успешный результат.

Например, `Either String Int` позволяет вернуть текст причины или полученное целое число. Схема показывает возможные формы значения такого типа.

```text
Either String Int
    |
    +-- Left  "Name is empty"
    |
    +-- Right 5
```

В этой схеме конкретный результат имеет один из двух конструкторов. Значение `Left "Name is empty"` содержит строку, а `Right 5` число. При этом оба результата могут иметь один общий тип `Either String Int`. Вызывающая сторона определяет исход по конструктору и получает соответствующие данные.

Буквы `e` и `a` являются параметрами типов. В записи `Either String Int` параметру `e` соответствует `String`, а параметру `a` соответствует `Int`. Они могут обозначать разные типы, поскольку причина отказа и успешный результат выполняют разные роли.

## Проверка значения

Например, учебная программа принимает название и вычисляет его длину. По правилам задачи пустая строка считается недопустимой. При таком входе функция должна сохранить понятную причину отказа.

```haskell
nameLength :: String -> Either String Int
nameLength [] = Left "Name is empty"
nameLength name = Right (length name)
```

В этом коде образец `[]` распознаёт пустую строку. Для неё возвращается `Left` с объяснением `"Name is empty"`. Остальные строки переходят ко второму определению, которое вычисляет длину и помещает её в `Right`.

Применение `nameLength "Cedar"` даёт `Right 5`. Для `nameLength ""` результатом будет `Left "Name is empty"`. Сигнатура описывает оба случая сразу, поэтому результатом функции всегда является `Either String Int`.

Конструктор является частью результата. Значение `Right 5` можно разобрать и получить из него число `5`, а сам результат проверки используется с учётом обоих возможных исходов. Это сохраняет причину отказа до того места программы, которое решает, как с ней поступить.

## Полная обработка исходов

Сопоставление с образцом позволяет отдельно обработать `Left` и `Right`. Каждая ветвь получает доступ к значению внутри соответствующего конструктора. Например, другая функция может сформировать статус названия по результату проверки.

```haskell
nameStatus :: String -> String
nameStatus name =
  case nameLength name of
    Left reason -> "Rejected: " ++ reason
    Right count ->
      if count < 4
        then "Short name"
        else "Name accepted"
```

В этом коде ветвь `Left reason` получает строку с объяснением и добавляет к ней начало сообщения. Ветвь `Right count` получает длину типа `Int` и выбирает статус по её значению. Оба пути возвращают строку, которая становится результатом `nameStatus`.

Для `nameStatus ""` результат равен `"Rejected: Name is empty"`. Применение `nameStatus "Li"` даёт `"Short name"`, а `nameStatus "Cedar"` даёт `"Name accepted"`. В одном месте собрана обработка всех исходов проверки.

В полном `case` присутствуют обе ветви. Даже если большинство входов допустимы, причина отказа остаётся частью контракта функции. При нескольких проверках разные причины можно возвращать разными значениями `Left`, сохраняя общий тип результата.
