В этом уроке мы изучим безопасное чтение целого числа из строки через `readMaybe`. Разберём выбор типа результата и обработку неудачного разбора. Мы научимся отдельно проверять запись числа и допустимость полученного значения для задачи.

Числовые данные часто приходят в виде текста. Строку можно прочитать как число только тогда, когда её запись соответствует выбранному числовому типу. При этом успешно прочитанное число ещё может нарушать правила предметной области. Например, датчик принимает ограниченный диапазон температур, хотя тип `Integer` допускает гораздо больше значений.

У такого вычисления есть две самостоятельные проверки. Первая отвечает, получилось ли прочитать число. Вторая проверяет уже полученное число по правилам задачи. Разные результаты этих проверок помогают объяснить причину отказа.

## Чтение с результатом Maybe

Модуль `Text.Read` предоставляет функцию `readMaybe`. Для чтения целого числа её можно использовать с конкретным результатом `Maybe Integer`. Успех представлен через `Just` с числом, неудачный разбор через `Nothing`.

Например, подготовим функцию для чтения текстового показания температуры.

```haskell
import Text.Read (readMaybe)

readTemperature :: String -> Maybe Integer
readTemperature text = readMaybe text
```

В этой функции сигнатура выбирает тип `Integer` для содержимого успешного результата. Применение `readTemperature "23"` даёт `Just 23`, а `readTemperature "warm"` даёт `Nothing`. В обоих случаях результат имеет тип `Maybe Integer`, поэтому неудача явно описана данными.

Сама `readMaybe` поддерживает чтение значений разных типов. Здесь мы используем её специализацию для целого числа. Выбранный тип можно также указать непосредственно у выражения через `::`, например `(readMaybe text :: Maybe Integer)`. Аннотация позволяет явно закрепить нужный тип результата в месте чтения.

## Что считается записью числа

Функция `readMaybe` проверяет всю строку по стандартным правилам чтения выбранного типа. Пробелы вокруг числа допускаются, а посторонний текст после него приводит к `Nothing`. В таблице приведены результаты для типа `Maybe Integer`.

| Входная строка | Результат |
| --- | --- |
| `" 23 "` | `Just 23` |
| `"-3"` | `Just (-3)` |
| `"- 3"` | `Just (-3)` |
| `"+3"` | `Nothing` |
| `"12 units"` | `Nothing` |
| `"12 3"` | `Nothing` |
| `"12.0"` | `Nothing` |
| `""` | `Nothing` |

Здесь знак минуса разрешён, в том числе с пробелом перед цифрами. Знак плюса перед числом не принимается. Дробная запись тоже не подходит выбранному типу `Integer`. Эти правила задаёт стандартное чтение этого типа, поэтому отдельная проверка только на десятичные цифры не описала бы его поведение полностью.

Например, также принимаются скобки и шестнадцатеричная запись. Строка `"(12)"` даёт `Just 12`, а `"0x10"` даёт `Just 16`. Подробности доступного формата определены в [документации стандартного чтения](https://hackage.haskell.org/package/base/docs/Text-Read.html). Для собственных ограничений на формат потребовалась бы отдельная задача разбора.

## Проверка допустимого значения

Допустим, учебный датчик настроен на температуры от `-20` до `50` включительно. Его диапазон можно проверить отдельным предикатом, который получает уже известное целое число.

```haskell
inSensorRange :: Integer -> Bool
inSensorRange degrees = degrees >= (-20) && degrees <= 50
```

В этом коде `inSensorRange 23` даёт `True`, а `inSensorRange (-30)` даёт `False`. Предикат ничего не знает о первоначальной записи числа. Число `-30` может быть корректно прочитано из текста и при этом нарушать ограничение датчика.

Схема показывает, какие данные нужны каждой проверке.

```text
      String
        |
  readTemperature
        |
        +-- Nothing          число неизвестно
        |
        +-- Just degrees
                   |
          inSensorRange degrees
                   |
                   +-- True    допустимое показание
                   +-- False   вне диапазона датчика
```

На этой схеме проверка диапазона получает число только после успешного чтения. Для строки `"-30"` функция `readTemperature` возвращает `Just (-30)`, а предикат для полученного числа возвращает `False`. Для строки `"cold"` разбор даёт `Nothing`, поэтому числа для проверки диапазона нет. Сам предикат остаётся обычной функцией `Integer -> Bool`, его можно использовать и для показаний, полученных без текстового ввода.

Объединённая проверка могла бы возвращать допустимое показание как `Maybe Integer`. Тогда неверная запись и выход за диапазон давали бы одинаковый результат `Nothing`. Такой результат сообщает об отсутствии подходящего значения, но теряет причину отказа. Для сохранения этой причины подходит уже знакомый тип `Either`.
