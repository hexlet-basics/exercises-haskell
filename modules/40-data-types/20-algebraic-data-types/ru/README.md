В этом уроке мы изучим собственные типы данных в Haskell. Разберём объявление вариантов через `data`, построение значений и извлечение их содержимого. Мы научимся описывать разные случаи одной задачи и полностью обрабатывать их сопоставлением с образцом.

В одной задаче могут встречаться несколько форм данных. Например, экран устройства может быть выключен, показывать сообщение или отображать ход выполнения работы. Для сообщения нужен текст, а для хода работы нужны два числа. Собственный тип позволяет перечислить эти случаи и указать, какие данные относятся к каждому из них.

## Объявление типа

Тип объявляется словом `data`. После него пишется имя типа, затем `=` и варианты значений, разделённые `|`. Например, состояние экрана можно описать так.

```haskell
data DisplayState
  = ScreenOff
  | Caption String
  | Progress Integer Integer
```

В этом объявлении `DisplayState` является именем типа. `ScreenOff`, `Caption` и `Progress` называются конструкторами значений. Они задают способы построить значение типа `DisplayState`. Имена типов и конструкторов начинаются с заглавной буквы.

Конструктор `ScreenOff` не хранит дополнительных данных и сам является готовым значением. Конструктору `Caption` нужна одна строка. Конструктору `Progress` нужны два целых числа, количество выполненных и общее количество действий. Схема показывает, что значения с разным содержимым имеют один тип.

```text
ScreenOff        ┐
Caption "Ready"  ├──> DisplayState
Progress 3 10    ┘
```

На этой схеме слева находятся три конкретных значения, а справа указан их общий тип `DisplayState`. У `ScreenOff` нет дополнительных данных, `Caption "Ready"` хранит строку, а `Progress 3 10` хранит два числа. Различие содержимого не мешает использовать все три значения там, где ожидается `DisplayState`.

## Построение значений

Чтобы создать вариант с данными, конструктор применяют к значениям нужных типов. Например, программа может описать сообщение о готовности и выполнение трёх действий из десяти.

```haskell
readyScreen :: DisplayState
readyScreen = Caption "Ready"

workingScreen :: DisplayState
workingScreen = Progress 3 10
```

В этом коде `readyScreen` и `workingScreen` имеют одинаковый тип `DisplayState`. Первый хранит строку, второй два целых числа. Аргументы конструктора записываются через пробел.

Типы аргументов проверяются при компиляции. В следующем примере намеренно передана строка на место первого счётчика `Progress`.

<!-- lint-code-blocks: skip — намеренно неверный тип аргумента конструктора -->

```text
brokenScreen :: DisplayState
brokenScreen = Progress "3" 10
```

GHC отклоняет это определение. Ключевой фрагмент сообщения показывает ожидаемый и фактический типы.

```text
Couldn't match type ‘[Char]’ with ‘Integer’
Expected: Integer
  Actual: String
In the first argument of ‘Progress’, namely ‘"3"’
```

В строке `Expected` указан ожидаемый тип `Integer`, а в строке `Actual` фактический тип `String`. Литерал `"3"` имеет тип строки, хотя содержит цифру. Для первого счётчика нужен целочисленный литерал `3` без кавычек. Запись `[Char]` в первой строке сообщения обозначает тот же тип, что и `String`.

Имя типа употребляется в сигнатурах, а конструкторы используются для создания значений и их разбора. Эти роли можно увидеть в таблице.

| Запись | Роль |
| --- | --- |
| `DisplayState` | Тип состояния экрана |
| `ScreenOff` | Готовое значение типа `DisplayState` |
| `Caption` | Конструктор с типом `String -> DisplayState` |
| `Progress` | Конструктор с типом `Integer -> Integer -> DisplayState` |

В этой таблице конструкторы с данными принимают аргументы и возвращают значение объявленного типа. Поэтому после применения всех аргументов `Progress 3 10` получается одно состояние экрана.

## Разбор вариантов

Конструкторы можно использовать в образцах. При успешном сопоставлении имена внутри образца связываются с данными конкретного значения. Например, функция может получить текстовое описание состояния.

```haskell
screenText :: DisplayState -> String
screenText ScreenOff = "Off"
screenText (Caption text) = text
screenText (Progress completed total) =
  if completed >= total
    then "Complete"
    else "Working"
```

В этой функции образец `Caption text` выделяет строку и возвращает её. Образец `Progress completed total` выделяет оба числа и использует их в условии. Для `screenText readyScreen` результат равен `"Ready"`, а для `screenText workingScreen` результат равен `"Working"`. Выражение `screenText (Progress 10 10)` даёт `"Complete"`.

Скобки показывают границы одного составного аргумента. Запись `(Caption text)` описывает один аргумент функции `screenText`, построенный конструктором `Caption`. Имя `text` становится доступно только в соответствующем определении. У каждого варианта может быть свой набор таких имён.

Функция `screenText` перечисляет все конструкторы типа `DisplayState`, поэтому для каждого допустимого состояния найдётся подходящий случай. Если пропустить один из вариантов, вычисление для него может завершиться ошибкой неполного сопоставления. При добавлении нового конструктора нужно проверить и функции, которые разбирают этот тип.

Такое объявление типа называется алгебраическим. Оно объединяет выбор одного из вариантов и данные, которые хранятся внутри выбранного варианта. Для работы с ним достаточно явно построить значение конструктором и разобрать его форму в функции обработки.
